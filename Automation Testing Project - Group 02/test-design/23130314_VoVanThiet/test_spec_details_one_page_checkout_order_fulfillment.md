# Test Specification Details: One-Page Checkout & Order Fulfillment

**Project:** MahoCommerce Automation Testing  
**Environment:** Local MahoCommerce source in `maho/` (26.9.3)  
**Execution Tool:** Playwright Test / TypeScript  
**Design matrix:** [`test_design_one_page_checkout_order_fulfillment.md`](test_design_one_page_checkout_order_fulfillment.md)

## Automation Preconditions

- Use a disposable local database, reachable storefront/Admin, guest checkout enabled, and a Sales-permitted Admin test user. Keep secrets in ignored environment configuration.
- Prepare a unique run-scoped shippable product, physical destination, deterministic shipping/payment methods, and customer/address fixtures only for the corresponding cases. Fresh browser context/cart/order per test.
- Record store currency, tax, shipping, checkout settings and theme-specific UI. Do not assume five fixed accordion panels, exact route slugs, status labels, order ID format, or tracking exposure in the customer theme.
- Capture the generated order increment ID from the success page. Admin tests must operate only on run-created orders; cleanup must be retry-safe.
- This spec excludes generic cart CRUD/BVA, login/address-book management, coupon flows, and order double-submit/ID uniqueness scenarios assigned elsewhere.
